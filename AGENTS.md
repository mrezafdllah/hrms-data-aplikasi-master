# AGENTS.md

CBN HRMS — internship HR application. Monorepo of three independent apps, each deployed separately to Vercel (mobile via EAS). There is no root package manager or root-level build; treat each folder as its own project.

## Layout / ownership

- `hr-backend/` — FastAPI (Python 3.11, psycopg2 raw SQL) monolith. Single-entry `main.py`; auth in `auth.py` (JWT, roles are role-name strings: `Super Admin`, `Admin HR`, `Karyawan`); DB connection in `db_helper.py`. Uses a venv committed per-machine at `hr-backend/venv`.
- `hr-frontend/` — React 19 + Vite 8 SPA (plain JSX, not TS), Tailwind v4, react-router-dom v7. Pages in `src/pages/`, API layer in `src/utils/api.js`.
- `hr-mobile/` — Expo SDK 57 / RN 0.86 app in TypeScript. expo-router file-based routes live under `src/app/` (not root `app/`); API layer in `src/utils/api.ts`. See its own `hr-mobile/AGENTS.md`.

## Commands

Backend (run from `hr-backend/`):
- `venv\Scripts\python -m uvicorn main:app --reload` — serves on port 8000 (matched by frontend/mobile defaults).
- DB init is two steps: `venv\Scripts\python migrate.py` then `venv\Scripts\python init_admin.py` (seeds roles, companies, jobs, positions, and demo logins — Super Admin `admin123`, Admin HR `hr123`, employees `user123`), all defined in `init_admin.py`.
- `alter_db.py`, `migrate_emails.py`, `migrate_reset_token.py`, `update_fetch.py` are one-off data-patch scripts, not a migration framework.
- No test framework; verify via `GET /api/health` and manual smoke test.
- Requires `hr-backend/.env` (gitignored): `DATABASE_URL` (preferred over the `DB_*` fallback vars; local default points at Neon cloud), plus `JWT_SECRET`, and `SMTP_*` + `FRONTEND_URL` for password-reset email. Never commit it.

Frontend (from `hr-frontend/`):
- `npm install`, `npm run dev` (5173), `npm run lint` (ESLint 10 flat config), `npm run build`.

Mobile (from `hr-mobile/`):
- `npm install`, `npm start` / `npm run android` / `npm run web`.
- Expo SDK 57 is newer than most tutorials — always read https://docs.expo.dev/versions/v57.0.0/ before writing mobile code.
- `app.json` enables typed routes + React Compiler experiments; `expo-env.d.ts` is generated by `expo start`. Run it after changing route files/adding screens.

## Architecture notes / gotchas

- API responses and error `detail`s are in Indonesian; keep that convention.
- Base URLs are per-app, hardcoded/wired independently:
  - Frontend: `VITE_API_BASE_URL` env, else `''` when host is not localhost (same-origin on Vercel) else `http://localhost:8000` (`src/utils/api.js`).
  - Mobile: `EXPO_PUBLIC_API_URL`, else hardcoded `https://hrms-data-aplikasi-master.vercel.app/api`; in local Expo Go it auto-rewrites to the Metro host LAN IP on port 8000 (`src/utils/api.ts`). EAS `preview`/`production` pin `EXPO_PUBLIC_API_URL` in `eas.json`.
- Profile picture uploads (`/api/upload-profile-picture`) are stored as base64 data URIs in `users.profile_picture` — reliable on serverless, so don't "fix" uploads to rely on the `/uploads` file mount (it's ephemeral on Vercel).
- All deletes on companies/jobs are soft (soft `deleted_at`/`deleted_by`); positions are hard-deleted.
- Role/company boundaries are enforced server-side in SQL queries (`get_user_company_id`), not just in UI; Admin HR can only see/manage their own company's Karyawan.

## Git

- Two remotes: `origin` (GitHub `mrezafdllah/hrms-data-aplikasi-master`) and `gitlab` (gitlab.cybersblitz.co.id `INTERNSHIP/polindra-2026`).
- Branch tracking is non-obvious: `main` tracks `gitlab/backend`; local `gitlab-frontend` tracks `gitlab/frontend`. `origin/main` exists too. Verify remote/branch before pushing.
- No CI or pre-commit hooks; `dist/`, `node_modules/`, `venv/`, `.env*`, `.expo/` are gitignored.
